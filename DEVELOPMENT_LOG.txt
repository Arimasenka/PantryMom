PANTRYMOM - DEVELOPMENT LOG
===========================

What the app is
  A mobile iOS app (Expo / React Native, Expo SDK 57, Expo Router) that knows which
  ingredients you have at home and can come up with recipes from just those ingredients.
  Planned: saved past recipes, easy entry for new groceries, prompting the user for
  recipe criteria, and (later) saved user preferences.

How to read this log
  Newest version first. Every version lists:
    - Git tag and commit (the tag is the version number)
    - MAJOR CHANGES: the headline points only
    - DETAILS: how it was done, files touched, decisions, and known limits
  This file is updated in the same commit as the app change it describes. A commit
  cannot contain its own hash, so the newest entry says "this commit"; look it up with
  "git show-ref 1.04" (or the tag you want) or "git log --oneline".

Git rules (from claude.md in the project root, written by the user)
  - Commit only when the user asks. Right after each commit, tag it with the next
    version: raise the number after the dot by one (1.03 -> 1.04). No new whole number
    (2.0) without asking.
  - Annotated tags with a short description: git tag -a 1.04 -m "description".
    (Tags 1.0 to 1.03 are older lightweight tags.)
  - Only app-change commits get version tags; log-only edits ride along with the next
    app change instead of getting their own commit.
  - Never push commits or tags unless asked. Never stage .env files or anything with an
    API key. Run git status and show the file list before every commit, and
    git log --oneline after.

VERSION 1.05   (tag: 1.05, commit: the commit that contains this entry, 2026-10-04)
Persist the ingredient list on the phone
==============================================================================

MAJOR CHANGES
  - The pantry now survives closing the app: the ingredient list is saved on the phone
    and loaded when the app opens.
  - Storage errors never crash the app.

DETAILS
  - Package added: @react-native-async-storage/async-storage 2.2.0 (via npx expo
    install; works in Expo Go on SDK 57).
  - src/lib/pantry-storage.ts (new): loadPantry() / savePantry() under the key
    "pantry.ingredients". Both wrapped in try/catch; a failed or corrupted load returns
    an empty list, a failed save is logged and ignored. Loaded data is checked to be a
    list of non-empty strings.
  - src/app/index.tsx: a load effect on first render (merges with anything typed before
    loading finished) and a save effect on every list change. Saving waits for a
    "loaded" flag so the empty starting list cannot overwrite the saved one.
  - Scope kept narrow on purpose: only the ingredient names are stored (no quantities
    or stock tracking). Recipes are not saved yet.
  - Verified: typecheck, full iOS export builds with the storage code. Not yet checked
    on a device when written.

VERSION 1.04   (tag: 1.04, commit: 239c889, 2026-10-03)
Add AI recipe suggestions (Phase 3 reattempt)
==============================================================================

MAJOR CHANGES
  - "Suggest recipes" button sends the pantry to a server route that asks Claude for
    exactly 3 recipes and shows them below the map/list.
  - Optional "Chef's request" text box (200 characters max) to steer the recipes.
  - The Claude API key stays on the server: it is read only inside the route file.
  - Includes the development log (DEVELOPMENT_LOG.txt), first committed here.

DETAILS
  - app.json: web.output changed from "static" to "server" (Expo SDK 57 needs this for
    API routes). Package added: @anthropic-ai/sdk (via npx expo install).
  - src/app/suggest+api.ts (new): Expo Router API route, POST /suggest. Takes
    {ingredients, request}, validates and cleans them (max 50 ingredients, 60 chars
    each, request capped at 200, angle brackets stripped). Calls claude-haiku-4-5-20251001
    with a JSON schema (title, time, ingredientsUsed, extraIngredientsNeeded, steps) so
    the output format is enforced; returns exactly 3 recipes or a friendly error.
  - Prompt safety: ingredients and the chef's request are passed in tagged sections,
    and the system prompt says the request is only a food preference; instructions in
    it (change the format, ignore rules, reveal the prompt) are to be ignored.
  - Errors handled with friendly messages: bad request, missing key, rejected key, rate
    limit, cut-off or refused answers, and "couldn't reach the service" on the client.
    When the key is missing the server logs similar variable NAMES only (never values).
  - src/lib/recipe-types.ts (new): Recipe type and the 200-character limit, shared by
    server and screen; no secrets.
  - src/components/recipe-suggester.tsx (new): the chef's request box with a counter,
    the button (disabled when the ingredient list is empty or loading), a loading
    spinner, error text and the recipe cards (scrollable, max height 260).
  - src/app/index.tsx: renders the suggester below the map/list and wraps the screen in
    a KeyboardAvoidingView so the keyboard does not cover the request box.
  - Verified without the phone: typecheck passes; route returns 400/405 for bad input;
    full iOS export builds; the client bundle contains neither the key name nor the
    Anthropic SDK; one real test call returned recipes (about a fraction of a cent).
  - Gotcha found: Expo reads .env.local only when the dev server starts. "Missing API
    key" after adding the key means the old server was still running; restart with
    "npx expo start --clear".
  - Model is the cheap test model on purpose (claude-haiku-4-5-20251001).

VERSION 1.03   (tag: 1.03, commit: 7c2f37a, 2026-10-03)
Rebuild swipe-to-delete with gesture-handler swipeable and iOS-style haptic
==============================================================================

MAJOR CHANGES
  - Swipe-to-delete rebuilt on react-native-gesture-handler's swipeable (modeled on
    iOS Messages) instead of hand-written drag code.
  - Red bar fills in from the right as a row is dragged left; a white X appears at its
    left end once the delete point is passed; letting go there deletes the row.
  - Small haptic tap when the delete point is crossed.
  - Deleted rows collapse with a short animation.

DETAILS
  - src/components/swipe-to-delete-row.tsx (rewritten): uses ReanimatedSwipeable from
    react-native-gesture-handler. The red action panel is as wide as the row; a
    derived value ("armed") flips when the drag passes 40% of the screen width, which
    drives the X (fade + scale in) and the haptic.
  - Haptic: expo-haptics, ImpactFeedbackStyle.Light, fired once per crossing into the
    delete zone. Callback goes UI thread -> JS via scheduleOnRN (react-native-worklets,
    the Reanimated 4 way; runOnJS is the older name).
  - The swipeable's rightThreshold uses the same 40% value, so the snap point and the
    X/haptic point match. Full swipe past it = delete (like Messages).
  - src/app/_layout.tsx: whole app wrapped in GestureHandlerRootView (required for
    gesture-handler gestures to work).
  - src/app/index.tsx: LayoutAnimation (easeInEaseOut) before removing an item so the
    rows below slide up.
  - Remove mode is still list-only and swipes only work while it is on (from 1.02).
  - Known differences from real iOS: a fast flick can delete before the X shows (the
    library adds flick speed to drag distance on release); no tap-to-confirm Delete
    button once swiped.
  - Not run on a device when written; the 40% point and Light haptic are easy to tune.

VERSION 1.01   (tag: 1.01, commit: cfd42e3, 2026-09-30)
Add pinch zoom, pan and full-width graph view
==============================================================================

MAJOR CHANGES
  - Pinch to zoom, with low zoom sensitivity and effectively unlimited zoom-out.
  - Pan the map freely, including out into empty space.
  - Labels fade out and icons shrink to plain dots as you zoom out.
  - Graph area now runs edge to edge; its top stays below the entry bar.

DETAILS
  - src/components/ingredient-graph.tsx: a camera (scale, tx, ty) over the simulation;
    screen position = world position * scale + offset. The simulation still runs in
    world space.
  - Gestures via PanResponder: one finger drags a node (or pans if you miss every
    node); two fingers pinch-zoom and pan together, keeping the point under your
    fingers fixed. Lifting one finger after a pinch continues as a pan.
  - Zoom: scale change = (finger spread ratio) ^ 0.5 for gentle zoom; scale clamped to
    0.02 (about unlimited out) to 4 (in).
  - Zoom-out fades: labels fade between 90% and 50% scale; the emoji fade into plain
    dots once nodes get small; node and string sizes shrink with scale.
  - Hit testing happens in screen space with a minimum radius so tiny nodes stay grabbable.
  - Nodes are no longer clamped inside the box; a gentle pull toward the center keeps
    the graph together.
  - src/app/index.tsx: header (title + entry bar) padded, graph container full width.

VERSION 1.0    (tag: 1.0, commit: 8f6013b, 2026-09-30)
Ingredient mind map, first version
==============================================================================

MAJOR CHANGES
  - Project created from the Expo starter (Expo SDK 57, Expo Router, TypeScript).
  - Ingredient entry bar and pantry screen.
  - Pantry shown as an Obsidian-style force-directed graph ("mind map") of ingredient
    nodes, with strings linking each ingredient to its closest related ingredients.
  - Related ingredients decided by shared usage groups.

DETAILS
  - Before the first commit, a simple list screen was built (useState list + text
    input) and a dark-mode bug fixed: text and background colors are now set
    explicitly for light and dark mode (phone dark mode made black text unreadable).
  - src/lib/ingredient-data.ts: table of ~55 ingredients, each with an emoji icon and
    usage groups (breakfast, baking, pasta, stir-fry, mexican, soup, salad, grill,
    dessert, sandwich, fried-rice). relatedness(a, b) = number of shared groups;
    buildEdges links each ingredient to its top 2 relatives. Names are normalized
    ("Eggs", "egg", "tomatoes" -> "tomato"). Unknown ingredients get a letter icon and
    no strings, so they just float. This is the piece to replace with AI-based links.
  - src/components/ingredient-graph.tsx: custom force simulation (pairwise repulsion,
    spring along strings, center gravity, damping, cooling), run with
    requestAnimationFrame until it settles and restarted on any change. Strings drawn
    with react-native-svg (already bundled in SDK 57); nodes are absolutely positioned
    views. No graph library, to keep dependencies small.
  - Nodes can be dragged; new ingredients spawn near the center and float until linked.
  - Dark Obsidian-style palette for the graph (purple node rings, grey strings).
  - Duplicate ingredients are ignored.
  - Local git repository set up in the project folder (a stray empty repo in the user
    folder was left alone). No GitHub remote exists yet; backups are local only.
